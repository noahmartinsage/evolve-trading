## §1 · 为什么这批情报值得对标

对标的前提是两者在**同一个问题上给出不同解法**。先确认这一点成立：

本系统第 4 层要回答的是「**这笔交易凭什么可以自动做出去**」。情报里五个主题表面上互不相关，
但把它们的机制性结论并排放，会发现它们各自切的是同一个问题的**不同侧面**：

| 情报主题 | 它实际在回答的子问题 | 与 EVOLVE 的关系 |
|---|---|---|
| Web4.0 代理经济（x402 / ERC-8004 / MCP） | 结算与信任的**接缝**在哪 | ✅ 我们有双通道（CEX + DEX），接缝正是我们的核心难点 |
| AI Coding 多 Agent 验证优先 | 「谁说的」如何变成「谁验过」 | ✅ 我们有 LLM 提案器，但没有对它的**声称**做过核验 |
| Skill 经济与供应链安全 | 能力如何被封装成**小、锋利、可验证**的资产 | ⚠️ 我们的风控纪律长期只存在于代码里，未沉淀为可复用资产 |
| Crypto AI 量化成熟度 | 预测 / 执行路由 / 风控闸门三者如何分工 | ⚠️ 我们只有预测与执行，**没有成本闸门** |
| 决策大脑生产化 | 决策如何做到**可解释 + 可审计** | ⚠️ 有事件流，但缺少「裁决」形态的留痕 |

**结论**：这五份情报不是在提供功能清单，而是在提供一张**接缝的剖面图**。
EVOLVE 在链上执行、审计治理、准入治理三块走得更远（见 §3 反向项），
但在「自动做出去」这个动作的**前置把关**上，缺了整整一层 —— 这就是本轮内化的边界。

## §2 · 情报解剖：从结论倒推机制

不照抄功能名，只抽**机制性结论**（可证伪、可对照的）：

### 2.1 交易成本是决策闸门，不是事后统计项

**结论**：`lazi-nhr/AI-Trading-Agent` 的样本外结果是，同一策略在
**0 / 1.44bps / 4.50bps** 三档费率下，夏普与最大回撤**急剧劣化**。
即「回测赚、实盘亏」的差额主要不是模型能力问题，而是**成本项漏算**。

**对照本仓库（内化前）**：全仓库**没有一处代码知道「做这一笔要付多少钱」**。
决策层看到的只有「预期收益」。这不是「成本算得不精确」，而是**根本没人算**。

### 2.2 信任是三层注册表，不是一维分数

**结论**：ERC-8004 把信任拆成 **Identity（身份）/ Reputation（声誉）/ Validation（验证）** 三个注册表。
关键语义是「**未知 ≠ 中等声誉**」—— 没有样本的对手方不能被当成「还行」。

**对照本仓库（内化前）**：没有任何对手方概念。CEX 与 DEX 被当成「同一个世界里的两种执行方式」。

### 2.3 双通道统一的难点在**结算接缝**，不在下单接口

**结论**：x402 / Web4.0 的代理经济瓶颈被定位在**支付互操作性**上 ——
而「CEX + DEX 统一结算」是其中最难的一道缝。

**对照本仓库（内化前）**：`reconciliation.ts` 只做**单场所**余额对账。
跨通道借据（我欠哪个域多少、哪个域欠我多少）完全不存在。

### 2.4 自主支付需要人类在环，且批准必须是**一次性的**

**结论**：「合理的误购」在自动支付里必然发生，代码无法自我批准。
一次性消费 + 有效期（TTL）是这套闸门的两个必要属性 ——
**陈旧审批比没有审批更危险**，因为它会放行一个早已不成立的市场前提。

**对照本仓库（内化前）**：有 killswitch、有 live 门禁，但没有「具体某个动作待人点头」的队列。

### 2.5 「谁说的」必须能变成「谁验过」

**结论**：`LLM_trader` 显式做了**声称核验** —— 把模型自述的趋势 / ADX / ATR / 盈亏比
与实测指标交叉核对。要点是 `UNVERIFIABLE ≠ SUPPORTED`：
「核不了」和「核过了」是两件事，压成一个布尔就必然有一类被当成另一类。

**对照本仓库（内化前）**：LLM 的 `rationale` 是自由文本，直接进决策流，无人核对。

### 2.6 上下文是有预算的资源，约束的存活不能取决于运气

**结论**：多 Agent 验证优先范式里，提示词的组成是**分级 + 可裁剪 + 必须有报告**的。
缺失的约束不能静默消失。

**对照本仓库（内化前）**：提示词是字符串拼接。心法库一长，风控约束就可能被挤出窗口，
而模型不会报错 —— 它只是开始提越界提案。

## §3 · 优劣对比矩阵（含反向项）

| 维度 | 外部范式 | EVOLVE 内化前 | 判定 |
|---|---|---|---|
| 成本建模 | 费率三档做敏感性 + 作为策略筛选条件 | **完全缺失** | ❌ 直接内化 |
| 对手方信任 | 三层注册表，未知 ≠ 中等 | 无对手方概念 | ❌ 直接内化 |
| 跨通道结算 | 接缝是对账层，同名不同域不可合并 | 仅单场所对账 | ❌ 直接内化 |
| 自主动作审批 | 人类在环 + 一次性消费 + TTL | 只有全局 killswitch | ❌ 直接内化 |
| 声称核验 | 声称 vs 实测交叉核对，三态裁定 | 无 | ❌ 直接内化 |
| 上下文预算 | 分级裁剪 + 裁剪必须可见 | 字符串拼接 | ❌ 直接内化 |
| 风控参数 SSOT | `risk_constants.py` | `riskConstants.ts`（已内化） | ✅ 已有，反向优势 |
| 物理拦截管线 | 插件式热插拔 | `interceptors.ts`（9 道，可开关重排） | ✅ 已有 |
| 账本语义 | 事件流 | 只追加链 + 持久化校验 | ✅ 已有且更严 |
| 提示词口径 == 代码口径 | 每轮插值风险预算 | `renderRiskBrief()` 插值 | ✅ 已有（R20 轮内化） |

**一句话**：情报给出的是一张「接缝剖面图」；EVOLVE 在**执行与治理**侧已经比这些项目走得更远，
缺的是**动作前置把关**这一整层。所以本轮只补这一层，不重做已有部分。

## §4 · 已内化清单（6 模块 + 15 参数 + 16 端点 + 1 面板 + 1 门禁）

### 4.1 成本硬约束闸门 — `server/costModel.ts`

**形态**：`assessEdge()` 返回的不是数字而是**裁决**（7 种）、带中文完整句 `reason`、并留存完整成本构成。

| 设计点 | 实现 | 为什么这么设计 |
|---|---|---|
| 成本是闸门不是报表 | `assessEdge()` 返回 `verdict` 而非 `cost` | 事后统计永远追不上已经下出去的单 |
| 假设缺失即拒绝 | `MISSING_COST_ASSUMPTION` | 最贵的失败模式是「某个成本项没被建模，静默按 0 计入」 |
| 名义本金下限 | `NOTIONAL_TOO_SMALL` | 固定成本（gas/桥费）不随规模等比缩小 |
| 冲击上限 | `IMPACT_TOO_HIGH` | 池深不足是**结构性不可行**，与方向判断无关 |
| edge 必须盖过成本 N 倍 | `MIN_EDGE_COST_MULTIPLE = 3` | 含义是「成本估算错到 3 倍才会由赚转亏」 |
| 成本占比上限 | `MAX_COST_SHARE_BPS = 120` | 帮人区分「该调参数」还是「该加仓」 |
| 口径同源自检 | 启动时断言 `CEX_EXPECTED_SLIPPAGE_BPS === DEFAULT_EXEC.slippageBps` | 两处不同源**不报错**，只表现为「回测年化 30%、实盘 4%」 |

**两个建模选择值得单独记下**：

*恒定乘积 AMM 的冲击率是 `N / D`，不是 `N / (2D)`。*推导（附在代码注释里，免得后人重推）：
投入 `N` 个报价单位，按 `x·y=k` 得 `ΔB = B·N/(D+N)`，
故**平均成交价** `= N/ΔB = P·(1 + N/D)` ⇒ 单腿冲击率 `= N/D`。
含义：**非线性**（规模翻倍，冲击成本翻 4 倍）、`poolDepthUsdt` 必须指「报价侧可动用储备」而非池子总市值。

*CEX 分支拒绝推算滑点。*订单簿逐档吃单的冲击曲线无法由单一深度值还原。
早期版本把线性式硬套 CEX，得到「2 万美金砸出 40bps」（真实约 1~3bps）——
而荒谬的成本估计会**把所有正常交易都判成不划算**。
所以 CEX 分支要求一个**具名假设**，不接受「大概估个滑点」：两者都没有 → 拒绝放行。

### 4.2 对手方三档信任 — `server/counterpartyRegistry.ts`

身份 / 声誉 / 验证三档，8 条种子记录（3 CEX + 5 DEX，DEX 路由地址**直接取自执行层** `contractsByChain`，不抄一份）。

裁决顺序刻意不可调换：**隔离 > 未登记 > 未核验 > 声誉过低 > 无样本 > 通过**。
把「声誉过低」排在「未核验」之前，会出现「一个未核验但恰好分数高的对手方被放行」——
**声誉分本身也来自我们自己，无法替代对身份本身的核验**。

三条反直觉设定：

- `deriveScore()` 在 `samples === 0` 时返回 **`null`**，不是 `0` 也不是 `0.5`。「没数据」不是「数据不好」。
- 无样本 → `UNPROVEN`，拿 **0.5× 仓位**。刻意不是 1（无据可依）也不是 0（新人永远无法积累信用）。
- `setValidation(id, 'verified', …, by)` 拒绝 `auto:*` 署名 —— **可信度只能由外部注入，不能自封**。

### 4.3 跨通道结算义务台账 — `server/settlementLedger.ts`

核心是资产键 `assetKeyOf() = "${symbol}@${chainId | 'cex'}"`。
`USDC@8453` / `USDC@cex` / `USDC@42161` 是**三个不同资产**，`canNet()` 只在同符号**且**同域时为真。

- 幂等：同一 `intentId` 二次开立不产生第二条义务
- **终态不可复活**：`settled`/`disputed`/`void` 之后任何写入被拒 ——
  防的是「对账发现差异后把已结改回未结来自圆其说」，那会让账本失去作为证据的资格
- `void` 必须带 `note`：作废会改变敞口视图，不能静默执行
- `reconcile()` 四类差异（`ORPHAN_OBLIGATION` / `MISSING_OBLIGATION` / `AMOUNT_DRIFT` / `STALE_OPEN`）**只报告不自动修** ——
  「自动抹平差异」是对账层最危险的功能，因为它把「两套账不一致」这个事实本身擦掉了
- 跨域提示单独列出，**刻意不并入净额**

### 4.4 人类在环审批闸门 — `server/approvalGate.ts`

- `paper` 免审批（不出真实资金），`live` 按门槛
- **结构性动作不看金额一律需要审批**（`bridge_transfer` / `venue_outbound_enable` / `policy_restore` / `counterparty_quarantine`）。
  判据是「这个动作会不会改变系统的能力边界」，不是「它涉及多少钱」
- 未知动作类型 → 落到**更严**的一侧（Fail-Closed）
- `decide()` 对 `live` 拒绝 `auto:*` 审批人 —— 一个可自我批准的闸门等价于没有闸门
- `gate()` 是唯一入口：找到「已批准且未消费」的同 `dedupeKey` 记录 → **消费它**并放行；找不到 → 建一条待批并拒绝
- TTL 过期即失效且**不补批**

### 4.5 声称核验 — `server/claimValidator.ts`

**三态裁定**：`VERIFIED` / `REJECTED` / `UNVERIFIED`。
理由的抽取用**确定性正则**而不是再调一次模型 —— 校验器的可信度必须高于被校验者，
而正则的行为完全可预测、可复核、可进 CI。

跨周期可比性守卫：声明 `timeframe` 与 `facts.timeframe` 不一致 → `UNVERIFIABLE`（不可比），
而不是「碰巧数字对上就算一致」。声明未标周期时比对成立，但**理由里必须写明按哪个口径比的**。

`requireVerified` 默认 `true`（只有 `VERIFIED` 放行）；置 `false` 时 `UNVERIFIED` 放行，
但 **`REJECTED` 任何配置下都不放行** ——「发现矛盾」从来不是可以配置放宽的条件。

### 4.6 上下文预算装配 — `server/contextBudget.ts`

**预留制**而非「边填边看」：先给强制块留位，再按 `(priority, id)` 装其余块。
两者的差别很实质 —— 边填边看会让强制块的存活**取决于它前面恰好没有大块**，
即「能不能看到风控约束」取决于心法库的大小。

- 强制块放不下 → **整体失败**（`ok: false`），绝不「少给一条约束然后继续」
- 丢弃 / 截断全部记入 `droppedIds` / `truncatedIds`，配 `renderBudgetReport()`
- 同输入同输出（按 `(priority, id)` 稳定排序），用 `Map` 而非平行数组保存渲染结果

### 4.7 参数进 SSOT 与执行层接线

`riskConstants.ts` 新增**组 7「成本硬约束与可信执行」**（15 个参数），
`riskConfig.ts` 补 schema（启动即断言键集一致）。三个好处一次拿到：
面板可调 → 提示词插值同源 → 执行闸门同源。

**接线**（这是最容易被跳过、也最容易「看起来做了」的一步）：

- `autopilot.ts` `tryOpenLong()` — 成本闸门放在**定完规模之后、预留之前**：
  成本随名义本金变化，不知道「打算做多大」时算成本等于算一笔虚构的交易；
  而必须在发单之前，否则等成本算出来时单已经出去了。
  拒绝时落 `AUTOPILOT_INTERCEPTED`，带 `submitted: false` + `plannedNotional`
  ——不标注的话，复盘会把日志里那个具体数字误读成「系统本来要下这么多」。
- `proposalEngine.ts` `generateProposals()` — 提示词改由 `assembleContext` 组装；
  风控口径与成本口径都是**强制块**；LLM 提案的 `rationale` 逐条过 `validateClaims`，
  `REJECTED` 的提案**直接丢弃**（不进入提案队列），结果记入 `claimChecks`。
  此处用 `requireVerified: false`：本引擎手里只有 15M K 线、没有高周期结构，
  实测输入本就稀缺，把「核不了」当「不合格」会让所有提案无差别阵亡 ——
  但「发现矛盾」照旧一律否决。
- `index.ts` — `/trust/*` 下 **16 个端点**（成本口径 / 试算 / 对手方 / 结算 / 审批 / 声称核验 / 上下文预算 / 汇总）。

### 4.8 前端「可信接缝」页

新增 `src/pages/SeamPage.tsx`（侧栏 + 路由 + TopBar 元数据同步接入），五块一页：
接缝健康度 KPI / 成本闸门试算器 / 对手方信任表（可点行看**裁决**而非只看记录）/ 跨通道结算与净额分组 / 审批队列 / 声称核验试算器。

图表口径上刻意**不用红绿**给成本项上色 —— 红绿在本项目里专属于涨跌，混用会让读者误判盈亏方向。

### 4.9 回归门禁 — `scripts/trusted-seam-smoke.ts`

**48 项断言**，无网络、无交易所依赖，已加入 `npm run ci`（`test:trusted-seam`）。
断言全部针对**语义不变量**，不是「函数返回了东西」：

- 记录之间状态独立（守住「两套口径」型缺陷）
- 终态不可复活 / 作废必须给理由 / 幂等
- 代码不能自我批准 / 批准一次性消费 / 过期不补批
- `REJECTED` 在任何配置下不放行
- 强制块放不下则整体失败（而不是丢约束继续）
- **默认参数不自相矛盾**（见 §6.3）

## §5 · 明确不内化（含理由）

| 情报项 | 为什么不内化 |
|---|---|
| 多 Agent 对抗辩论（propose → debate → risk gate） | 本系统当前是单提案器 + 确定性网格。加辩论层会引入**难以归因的随机性**，而现阶段更缺的是「闸门」而不是「更多意见」。等闸门跑稳、有真实成交样本再评估 |
| Skill 供应链扫描（SkillSpector / AgentShield） | 属开发流程安全，不是交易系统运行时要件。本项目已用 `skills-security-check` 流程覆盖，不引入运行时依赖 |
| 容器级沙箱隔离 | 需要 Docker/Node 24+ 能力，属部署阶段（阶段 D）。当前用 Node 权限模型 + `--allow-fs-read` 收窄 |
| 高频 / 做市范式 | 架构不适用（本系统按 K 线巡检自治循环），已冻结为独立项目 |
| 跨链桥接的实际执行 | 本轮只做**记账与对账**，不做桥接调用。桥是有真实损失风险的链上动作，需人类在环审批就位后再评估 |
| 模型级「成本敏感提示词」微调 | 属模型训练范畴，非本仓库职责 |

### 6.3 过程中发现并修掉的 6 个真实缺陷

这些是内化过程**自身**暴露的缺陷，全部属于「不报错、不崩溃、只是安静地做错事」类型：

1. **默认参数互斥，DEX 通道被结构性关闭。**
   `MAX_COST_SHARE_BPS = 60` 恰好等于 DEX 往返 LP 费率地板（30 × 2）。
   结果是**任何** DEX 交易都被判「成本占比过高」，而每条拒绝理由看起来都很合理
   （「这一笔太贵了」），没有一条指向真因。
   → 默认值调到 120，并在 `costModel.ts` 启动时**断言**该上限必须高于地板。

2. **跨域提示被自己的过滤条件静默吃掉。** `netting()` 的跨域检测写成「取正数那一侧」，
   当两侧都是净交付时 `amount <= 0` → 整条提示被过滤掉。
   而「两个域同时欠着同一种资产」恰恰是最需要被看见的情形。
   → 改为「两侧净额绝对值的**较小者**」（这才是「朴素净额会错误抵消多少」）。

3. 同一对域被**重复报告两次**（`a→b` 与 `b→a`）。告警数量虚高的最终后果是没人再看它 ——
   「告警太多」和「没有告警」效果相同。→ 只枚举无序对。

4. **CEX 冲击被线性外推**，给出「2 万美金砸出 40bps」的荒谬结论，
   会把所有正常 CEX 交易判成不划算。把闸门焊死与不设闸门一样糟。
   → CEX 拒绝推算，只认具名假设。

5. **声称核验最初是两态**（通过 / 不通过），导致「全部核不了」返回的 `ok` 与「全部核过」相同。
   把 `UNVERIFIED` 折进「通过」，就是又造了一台给幻觉盖章的机器。→ 改三态。

6. 上下文装配用**平行数组**（`parts[]` + `included[]`）保存渲染结果，
   顺序一变就错位。→ 改用 `Map<id, text>` 键查。

> 另有一处「文档与代码漂移」：`costModel.ts` 文件头的建模说明仍写着
> 「CEX 用线性式会高估成本，方向安全」——这与后来实现的「CEX 拒绝推算」相反。
> 已同步修正：**注释描述的必须是真的在跑的那套逻辑**，否则下一个人会照注释改回去。

### 6.4 遗留问题与既有红灯的真因（不修饰）

> 其中 **`test:autopilot` 的归因需要一条重要补充**：当时写的是"换 `breakout` 族即可通过"，
> 实际上**更深的根因**是 `ema-rsi` 族的入场条件 `price > EMA && rsi < lower` **数学上不可能成立**
> （2400 根 K 线里 0 次），以及 `marketRegime` 默认拉**真实 Binance** 数据导致测试随行情波动。
> 「换策略族」只会把缺陷藏起来，不会修掉它。

- **`test:autopilot` 红，且本轮发现了它的真因**：烟测 pin 的 `rsi-rev`（均值回归族）
  在单边上行行情里**永远不产生多头入场信号**，于是永远走不到 `tryOpenLong`，
  持仓恒为零 → 目标价永远达不到。换成 `breakout` 族即可通过。
  这与成本闸门无关（`[cost]` 从未出现在该测试日志中）。建议后续修烟测的策略 pin。
- **`test:sandbox` 红**：沙箱文件读权限过宽（历史 P0·安全项），
  处置方案见 `DEV_PROGRESS.md`；本轮未触碰。
- **`backtest:golden` 红**：`boll-rev` 的 fitness 越界（`fitness-v2` 定义域 `-100..120`），
  属适应度函数的边界处理，与本轮无关。
- **合成测试里的结构目标位不真实**：`deriveStructureTarget` 取的是
  **真实 BTC 的 24h 结构阻力**，而烟测喂的价格是 100~165，于是出现 `R:R = 16113` 这种数。
  这是测试夹具的口径不一致，不影响生产路径，但会让「成本闸门通过」这个信号在烟测里失真。
  §4.9 的接线断言因此只断言「闸门跑了 + 证据落账」，不断言「裁决合理」。**建议后续修夹具。**
- **`autopilot` 的成本闸门被上游短路**：ADX 过滤（合成行情 ADX 只有个位数）会在
  `tryOpenLong` 之前把流程拦下，所以闸门在默认烟测里根本不可达。
  §4.9 通过关闭上游两个过滤来**让下游可达**，不是因为上游错了。

## §8 · 给后来者的四条经验

**1. 闸门的第一失效模式是「没被调用」，不是「算错了」。**
本轮为验证接线花了不小的力气，原因是：闸门放在管线之后，上游一拦，它就永远不可达，
而**它不报错、不留痕**。所以断言必须经由真实执行链路，并检查证据是否落进账本 ——
「函数存在且单测通过」证明不了任何事。

**2. 两个默认值可以互斥，而且互斥的形态通常是一侧沉默。**
`MAX_COST_SHARE_BPS = 60` 与 `DEX_LP_FEE_BPS × 2 = 60` 组合起来让整条 DEX 通道不可用。
没有异常、没有日志、没有崩溃。**默认值之间的一致性需要用断言来守，
而不是靠人记得**；发现后应把不变量写成启动自检，而不是只改那个数字。

**3. 「无法验证」必须是一个独立结果，不能折进「通过」。**
三态裁定不是洁癖。把 `UNVERIFIED` 压进 `VERIFIED`，等于给无法核实的声明盖章；
压进 `REJECTED`，等于让所有「实测输入稀缺」的场景无差别阵亡。
**两侧都会让系统看起来在工作，而实际上它的判断已经失去意义。**

**4. 同名不同域是账本层最容易犯、也最贵的错。**
`USDC` 在 Base 上是合约地址，在 CEX 上是账户内记账。
把它们加起来做净额，会让「看起来已经轧平」与「实际还欠着」**同时成立**。
资产的身份必须是 `(symbol, domain)`，不是 `symbol`。
